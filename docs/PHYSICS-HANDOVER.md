### Specification

`data/specs/EDX_ALEVEL_PHYS_9PH0.json` is generated by `tools/physics/build_spec.py`
from Pearson's official specification PDF (Issue 3, November 2018, SHA256
`f91bef52…d90d3`; the build refuses any other revision). It replaces the earlier
unverified 13-topic/62-point catalogue.

- Leaves are the **191 official numbered statements** (`EDX_PHYS_S001`–`S191`),
  codes stored as strings, each with source PDF page and printed page.
- Tree: official Topic 1–13 (stable ids `EDX_PHYS_M1`…`M13`) → navigation group →
  statement. Groups reuse the earlier runtime skill ids (`EDX_PHYS_M2_2.1` etc.) so
  saved learned ticks keep their meaning. `js/config/spec-id-migrations.js` expands
  every earlier id into its statements when progress loads (`api.normalise`).
  `EDX_PHYS_M9_9.4` is legacy-only (its statements are in `EDX_PHYS_M9_9.3`).
  `EDX_PHYS_M10_10.1` (black body radiation) now sits under Topic 9, where Issue 3
  puts statements 153–155.
- AS 8PH0 (Issue 2, March 2016) uses identical statement numbers 1–96 (Topics 1–5).
  Those statements are `introduced_year: 12`; 97–191 are 13.
- Components: 9PH0/01 Advanced Physics I (Topics 1–3, 6–8, 90 marks, 1h45),
  9PH0/02 Advanced Physics II (Topics 1, 4, 5, 9–13, 90, 1h45), 9PH0/03 General
  and Practical Principles (all topics, 120, 2h30); 8PH0/01 Core Physics I
  (Topics 1–3, 80, 1h30), 8PH0/02 Core Physics II (Topics 1, 4, 5, 80, 1h30).
  9PH0/04 is the non-examined practical endorsement.

### Pipeline (all under `tools/physics/`)

| Step | Script | Notes |
| --- | --- | --- |
| OCR (scans only) | `ocr.py` | tesseract positions only, never replacement text |
| Extract | `extract.py SOURCES --output CANDIDATES [--ocr-dir OCR --ocr-overrides data/imports/physics/ocr-overrides]` | CropBox-relative (several 2020+ booklets have an inset MediaBox); `(n)` tariffs; MCQs use the "Total for Question" line; part regions include data printed after the tariff |
| Scheme index | `schemes.py` | "Question Number" tables, `*Q13`-style refs |
| Review sheet | `sheet.py CANDIDATE.json 500` | prints parts and text for review |
| Reviews | `reviews.py RESEARCH [glob]` (append `@x` to a parts cell to override a misread printed label) | compiles `review-src/<pid>.txt` lines `Q \| parts \| statements[; prereqs] \| e/m/h \| summary \| basis [\| i/s/g]` |
| Build | `build.py INVENTORY --sources … --candidates … --reviews … --only PID` | statement → `EDX_PHYS_Snnn`; year from statements; AS units may not tag statements > 96 |

## Checkpoint 4 — 2019 scans live, every public past paper imported (15 November 2026)

**Status: all 47 public past-paper booklets are live** (27 × 9PH0, 20 × 8PH0):
769 source questions, 1,630 scored units, 4,300 marks, 4,008 crops, 0 queued.
Tests 73/73, validation 0 errors, browser check PASS (AS 631 units, Year 13
only 521). Only the official SAMs remain for Physics.

The four June 2019 scans now reconcile exactly (80/80/90/90, 0 exceptions) using
**checked OCR overrides** in `data/imports/physics/ocr-overrides/<paper>.json`
(extractor v5). Each entry adds, corrects or drops one layout token on one page
(a question number, a part label such as "(i)" read as "(1)", a "(5)" tariff
read as "(3)", or a total line tesseract missed), is pinned to the source
SHA256, and was checked against the rendered page. Overrides never supply
question text: crops stay source pixels. On scans a question that starts below
the previous total line now starts after that line, so crops do not carry a
sliver of the previous question. Text booklets are unaffected by v5 (their
candidates still record v4; re-extracting gives identical parts).

To find tokens to check on a new scan, re-OCR the left margin and tariff column
at 4× (tesseract `--psm 11`) and compare against the OCR cache; confirm every
difference on the rendered page before adding it.

## Checkpoint 5 — official sample assessments; Physics import complete (15 November 2026)

**Status: complete.** `coverage.json` reports `complete`, 0 queued: 52 booklets
(47 past papers + 5 official SAMs), 856 source questions, 1,794 scored units,
4,760 marks, 4,422 crops. Tests 73/73, validation 0 errors, browser check PASS
(AS 692 units, Year 13 only 572).

SAMs (Issue 1, October 2014) are recorded in
`data/imports/physics/inventory/{9ph0,8ph0}-samples-inventory.json` as page ranges
of Pearson's two public collations. `tools/physics/prepare_samples.py` writes
byte-stable private caches (fixed PDF ID) and `source-page-provenance.json`; the
mark-scheme ranges carry `rotate_degrees: 90` because the landscape tables are set
sideways on portrait pages (only the page /Rotate entry changes, never content).
`build.py` and `finalize.py` accept a cache only when the manifest ties it to the
inventory's original checksum. SAM papers show as "Official sample", year null,
`is_official_sample: true`. Scheme crops can show a sliver of the collation's
sideways footer at the left edge; it is source pixels and was left as is.

Two small extractor/indexer fixes came with the SAMs: total lines set in small
caps ("(total for Question …") are recognised, and the scheme header match is
case-insensitive ("Question number"). Re-indexing every published scheme with
the new rule gives identical regions.

```sh
python3 tools/physics/prepare_samples.py data/imports/physics/inventory/9ph0-samples-inventory.json --originals ../physics-research/sam-originals --output ../physics-research/sources
```
